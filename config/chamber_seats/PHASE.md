# Chamber seats

This phase uses what is already on main. It does not replace it.

SOMA receives a Dojo packet only after that packet has been cleansed. Each of the nine chambers is an ecosystem. A TinyLlama in the chamber is the manager. A second seat holds the model closest to that chamber's language. The manager's parameters, and which language model is seated, can be swapped without changing the chamber. Light, colour, and embodiment are still unknown.

The file `seats.json` is the board for that. Nothing in it has been loaded.

## Verified on main

The latest commit on main is the WillowieData Samba share, 2026-07-02.

- Nine chakra modules exist, one directory each, and each reads its DNA blueprint.
- Nine DNA files exist in `config/dna_blueprints/`.
- Each enabled chakra service creates directories and then sleeps. The module warns that the Python agent is pending. Example: `chakras/anahata/module.nix`.
- `services/train-station/orchestrator.py` is a real HTTP service. It captures, validates, and routes by job type (build, deploy, store) to six octahedron vertices. It does not load a model. It does not check that a packet was cleansed.
- No branch before this one was the chamber-seat phase. `main` is the synced line. This branch starts from that commit.
